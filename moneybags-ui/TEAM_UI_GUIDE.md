# MoneyBag UI team guide

This is a JavaScript/MVVM Oracle JET 19 template. It is deliberately a UI shell: it contains shared navigation, themes, routes, and placeholder pages, but no live banking data yet.

## Non-negotiable ground rules

1. Work in `src/` only. `web/` is generated by Oracle JET and must never be edited by hand.
2. Keep this project JavaScript/MVVM. Do not add TypeScript, TSX, React, or a second routing framework.
3. Keep shared navigation, page routing, and global theme behaviour in their existing shared files. A feature page must not add its own navbar, theme toggle, or global stylesheet.
4. Use semantic CSS variables such as `var(--mb-surface)`, `var(--mb-text)`, and `var(--mb-accent)`. Do not hard-code hex/RGB colours in feature views.
5. Do not call a microservice directly from a page. Add an API adapter/service layer when integration starts, then keep request logic out of the HTML view.
6. Treat customer and banker actions as separate experiences. A banker-only action must never be exposed merely by hiding a customer button.
7. Do not edit another team's page, shared route, or API contract without agreement from that owner.
8. Keep data fictional in prototype screens. Never commit credentials, account numbers, customer documents, or production responses.

## Source map and ownership

| Location | Purpose | Who should change it |
| --- | --- | --- |
| `src/index.html` | Persistent shell: header, global navigation, footer, and route outlet | UI/platform owner |
| `src/css/app.css` | Shared layout, components, accessibility, and default MoneyBag tokens | UI/platform owner |
| `src/css/theme-presets.css` | Optional brand-palette overlays | Design system owner |
| `src/js/services/themeManager.js` | Restored and persisted light/dark preference | UI/platform owner |
| `src/js/viewModels/appController.js` | Route manifest and page metadata | UI/platform owner + relevant page owner |
| `src/js/views/public/` | Landing, catalogue, security, about | Public-area owner |
| `src/js/views/customer/` | Customer workspace pages | Customer-area owner |
| `src/js/views/banker/` | Banker workspace pages | Banker-area owner |
| `src/js/views/shared/` | Reusable neutral placeholder/empty content | UI/platform owner |

## Replacing a placeholder with a real page

Every route currently uses a deliberate placeholder. When you own a page, replace only that page's module mapping.

For example, to build Customer Accounts:

1. Create `src/js/viewModels/customer/accounts.js` for its JavaScript view model.
2. Create `src/js/views/customer/accounts.html` for its markup.
3. In `src/js/viewModels/appController.js`, change the `customer-accounts` route module from `customer/placeholder` to `customer/accounts`.
4. Keep its route path (`customer-accounts`) stable unless the UI/platform owner agrees to change it.
5. Retain the shared header and theme; the view should contain page content only.

Use the same matching folder/module convention for public and banker pages. Keep user-visible copy, loading states, empty states, errors, and primary actions in the page module that owns them.

## Current page map

- Public: landing, products, security, about.
- Customer: dashboard, profile, KYC, accounts, fixed deposits, cards, payments, bills, statements, notifications.
- Banker: dashboard, customers, KYC queue, accounts, cards, catalogue/pricing, accounting, end-of-day, IAM.

The route manifest is the source of truth for this template. Backend availability is separate: only connect a page once its API contract and authorization behaviour are agreed.

## Theming: one palette, two modes

The global header switches `data-mb-theme` on the `<html>` element between `light` and `dark`. `themeManager.js` stores the choice under `moneybags-theme` and falls back to the operating-system preference on first visit.

The default MoneyBag palette is at the top of `src/css/app.css`:

```css
html[data-mb-theme="light"] { /* shared light tokens */ }
html[data-mb-theme="dark"]  { /* shared dark tokens */ }
```

Change those two blocks to retheme the whole product. Every page should consume tokens, never make its own palette.

### Try the Vela Burgundy palette

The supplied Vela Burgundy Light palette is available as an optional preset in `src/css/theme-presets.css`. It uses Poppins, burgundy gradients only for high-emphasis areas, blush/white surfaces, and Vela's rounded-card scale.

For a persistent local preview, change the opening tag in `src/index.html`:

```html
<html lang="en" data-mb-theme="light" data-mb-palette="vela">
```

Run the app, use the existing dark/light toggle, and compare both Vela modes. Switch back to the default with:

```html
data-mb-palette="moneybag"
```

For a temporary browser-only experiment, run this in the browser console:

```js
document.documentElement.dataset.mbPalette = 'vela';
```

It resets after refresh. The light/dark toggle and the palette are independent, so a team can compare a brand palette in both modes.

### Add a future palette

1. Copy the two `vela` selector blocks in `src/css/theme-presets.css`.
2. Rename `vela` to a short, stable name such as `aurora`.
3. Change values only, keeping every `--mb-*` variable present.
4. Check both modes, keyboard focus, disabled states, success/error states, mobile layout, and readable text contrast.
5. Add the new palette name and a screenshot to the pull request description.

Gold/coral/accent colours are for emphasis, not the only indicator of a state. Use text, icons, labels, and sufficient contrast for errors, warnings, selected rows, and progress.

## UI quality checklist

Before requesting review:

- Use a single clear primary action per task area.
- Include loading, empty, error, and success states; never leave a blank content area unexplained.
- Use semantic HTML, meaningful button labels, visible keyboard focus, and a minimum practical 44px tap target.
- Keep normal text readable at 4.5:1 contrast or better; check both modes.
- Test a narrow viewport (390px) and desktop. There must be no horizontal overflow.
- Use Indian currency formatting consistently for prototype money values (`₹48,260`), but do not hard-code business calculations in the view.
- Use only gateway-visible public endpoints through the future UI adapter. Never surface an `/internal/...` endpoint as a browser action.

## Local commands

Run these from `moneybags-ui`. Use the `.cmd` forms because this machine's PowerShell policy can block `npm.ps1` and `npx.ps1`.

```powershell
npm.cmd run start
npm.cmd run build
npm.cmd run build:release
```

The installed Oracle JET 19.0.5 CLI advertises a `--cssvars` flag but rejects it during validation. Do not depend on that flag here: the application theme uses standard CSS custom properties in `app.css` and `theme-presets.css`, which are preserved and switched at runtime.

## Pull request expectations

Include the route(s) changed, target role(s), mocked/real API status, screenshots for light and dark modes, mobile evidence, and the output of `npm.cmd run build`. Keep generated output, `node_modules`, `.env`, logs, and credentials out of commits.
